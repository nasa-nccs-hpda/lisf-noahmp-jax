## 3. Findings that change how to read the results

1. **Maxima are not a measure of the port.** In CLSM, about 0.25% of the tiles (cold, partly frozen soil) turn 1 J/m2 of rounding in ground heat into up to 3 K in one step. Replaying the exact Fortran step-2 state with +-8 J/m2 noise on ground heat alone changes latent heat by up to 116 W/m2 (756 tiles above 2 W/m2); the real run differs by up to 112 W/m2 (1,339 tiles). Use p99 and the fraction of tiles within tolerance. Method and scripts: `Reports/clsm_sensitivity_20261022/`. Not tested for Noah-MP.
2. **Replay needs a full-domain dump.** A stride-sampled dump gave an apparent 3 K core mismatch that a full-domain dump (all 76,088 tiles, 50 intermediate arrays) did not reproduce.
3. **Output semantics matter.** LIS ignores undefined values for instantaneous history variables (Albedo keeps the last defined value of the window); `Rainf_f` is the precipitation before the rain/snow split. Both were found only by comparing with the real history file.
4. **gfortran MIN/MAX return the non-NaN argument**; `jnp.fmin/fmax` do the same. Without them a Noah-MP tile produced NaN after about 30 h and spread into the river network.

## 4. Open gaps (shipped as open, not closed)

1. Tolerances are the assistant's choice (owner decision) and are not reviewed; `Reports/ACCEPTANCE_CRITERIA.md` is still the DRAFT with placeholder numbers, plus the dated amendment at its end.
2. CONUS runs are 1 to 30 days (global 5 days); full-year runs exist only on the small SGP domain (Noah 3.6 Step 2 and Noah-MP 4.0.1: Noah-MP soil moisture p99 3.7e-4 m3/m3 after 365 d); CONUS 89-day Noah-MP 4.0.1 (Mar 3-May 1) done: Qle p99 3.8e-2 W/m2, SoilMoist p99 1.3e-4 m3/m3, single-tile maxima at snow melt (LOG.md 2026-10-24); behaviour of the other models over months is NOT KNOWN (CONUS Noah-MP 30 d: Qle/Qh p99 flat, soil moisture p99 from 4e-7 to 8.5e-5 m3/m3).
3. One reference build (GNU 14.2, serial, one core); no MPI LIS comparison.
4. Winter/spring 2017 for CONUS and global (July CONUS Noah-MP 14 d done: Qle p99 1.05e-2 W/m2; 89-day spring CONUS Noah-MP 4.0.1 done: Qle p99 3.8e-2 W/m2); NLDAS-2 and MERRA-2 forcing only. History files: Fortran also writes forcing and static diagnostics on 4,259 mostly-water CONUS cells (and static fields on 27,756 ocean cells) where JAX writes the missing value (no open-water tiles in the port); compare_hist reports them as 'NaN only in the new run'.
5. The freeze/thaw sensitivity test was done for CLSM only.
6. 12-member case: only the mean-field history difference was checked; the ensemble spread itself was not compared.
7. Only the assistant has run any of this; no second person, no LIS scientist review.
8. CLSM from a uniform summer coldstart (July 1 2017, 288 K, 30% soil moisture) is NOT reproduced: Qle p99 31 W/m2 after 24 h (about 80 wet-canopy tiles go chaotic in the first steps; JAX's compiled code fuses multiply-add, the Fortran rounds twice; `clsm_jax.nofma` fixes the SATCAP case, 2 tiles remain). Mosaic and Noah 3.3 July 2 d are fine (Qle p99 0.04 and 7e-4 W/m2); CLSM Feb 7 d from coldstart has Qle p99 0.004-0.006 W/m2 after day 1. A spun-up test (June 24 start, 9 d) shows the same, so this is not only a coldstart artifact (a no-FMA run, XLA_FLAGS=--xla_cpu_max_isa=AVX, behaves the same after day 1; the failure rate is ~5e-5 per tile and step in ill-conditioned freezing/wet-canopy branches, LOG 2026-10-22 ~19:30). Characterised (LOG 2026-10-22 ~21:30): ~1% of tiles (wet, densely vegetated: Florida, Gulf coast, south Texas) differ by >20 W/m2; the other 99% are accurate (median |dQle| 1e-3 W/m2, domain-mean Qle/Qh bias <= 0.02 W/m2, RMSE 0.3-4 W/m2); open-loop replay of the Fortran July call dump shows the core is right except on those ill-conditioned wet-canopy tiles. Documented limit, not fixed.
9. Test suite is small: `tests/` (pytest, 3 min) replays seeded samples of recorded Fortran calls for Noah 3.3, Noah 2.7.1, Noah-MP 4.0.1, Noah-MP 3.6 and the CLSM core (p99 limits); nothing automated for Mosaic, HyMAP2, DA, the forcing readers or the history writers (those are the closed-loop comparison scripts named in `LOG.md`).

## 5. The parallel runner (`gpu/run_variants.sh`) and its first run

Submits one exclusive V100 node per timing pair (Fortran, then JAX on the same node: CLSM 1 d, Noah-MP + HyMAP2 2 d), one shared node for the Noah-MP 7-day JAX run (compared with the stored Fortran reference), and a dependent summary job (`afterany`) that writes `gpu_runs/<name>/SUMMARY.md`. First real run `variants_20261022_a` (jobs 37944931-37944934, all finished): CLSM pair Fortran 5:54.55 vs JAX 25.5 s (13.9x); HyMAP2 pair Fortran 21:07 vs JAX 100.2 s (12.6x, gpu005); Noah-MP 7 d JAX 130.8 s (gpu013). Differences against the Fortran output: CLSM identical to the earlier run; HyMAP2 and 7-day Qle p99 2.9e-3 and 7.5e-3 W/m2. The summary job itself failed on the first try (system Python 3.6 lacks `capture_output`); fixed and the summary regenerated by hand, so the dependent job has not been re-verified. `compare_hist` flags 'NaN only in the new run' for the forcing diagnostics of 4,259 non-land grid cells and for static fields on 27,756 cells: the Fortran writes these over the full grid and the JAX history only for land tiles; not a physics difference (Qle is finite on exactly the same 76,180 cells).
